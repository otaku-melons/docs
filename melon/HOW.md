# How it works?
To understand how Melon works you need to go through its main commands step by step.

## 📦 parse
Command takes title slug and name of the parser that should process it. Than **Melon** launch source operator, which detects content type by slug and runs corresponding content submodule. In turn it creates struct of descriptive JSON title format and put title information inside, but without chapters content (no slides or paragraphs).

If title was parsed early, **Melon** loads content from local descriptive file and merge it with generated by content submodule struct. Thus, after each parsing descriptive file contains fresh title information, and the contents of the chapters are inherited between sessions. If we still have any empty chapters, **Melon** call the amend process: for every chapter without content it tries to get slides or paragraphs.

At the end system downloads covers and persons images, save descriptive file and clears temporary data.

## 🔧 repair
We can repair only early parsed title. In this case **Melon** read local descriptive file, search target chapter for repairing and newly call amend process for it. It can be useful when chapter was edited on server and you want to get latest changes.

## 🖼️ get
By this command **Melon** downloads image by link from source server. System calls `temp_image()` method of source operator and after downloading in parser temporary directory replaces file at another path if specified.

## 🏗️ build
In process of build system read local descriptive file and transfer in to selected build system. If chapters contains images, they will be downloaded by calling `temp_image()` method of source operator on the fly. As result **Melon** put readable content in `{OUTPUT_DIR}/{PARSER}/content` by default.

## 🗃️ collect
Parse everything or just one title? This is inconvenient. Instead parsing titles manually one after another, you may collect several slugs from server by using this command. Usually sites provides catalog, and collect can get slugs from it by 3 parameters:

- **pages** – count of catalog pages.
- **filters** – catalog filters (query parameters for example, but each parser can use own filters).
- **period** – period in hours from now in past in which titles was updated.

Collecting result stored in `{TEMP_DIR}/{PARSER}/collections/{COLLECTION}.txt` file by default and can be parsed by run `melon parse --collection {COLLECTION} --use parser`.
